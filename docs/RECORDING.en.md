# Demo recording

Finished video: [PurchaseFlow procurement approval and Odoo draft verification](assets/purchaseflow-demo.mp4) · [Simplified Chinese subtitles](assets/purchaseflow-demo.zh-CN.srt).

## Recording contents

1. Show the procurement overview and role to-dos.
2. The requester creates and submits a purchase request.
3. The department manager approves; a high-value request goes to a different finance user for review.
4. Show the real draft purchase order created in Odoo and independently read back.
5. Show the UNKNOWN state where real Odoo committed but the application did not receive the creation response.
6. Procurement performs a read-only query by the original intent, verifies, and closes.
7. View the n8n intake and daily digest workflows and the actual digest email in Mailpit.

## Reproduce the recording

From the repository root:

~~~powershell
pwsh ./scripts/start-demo.ps1
pwsh ./scripts/verify-demo.ps1 -ExerciseN8nWorkflows
pwsh ./scripts/run-erp-unknown-demo.ps1
cd frontend
npm ci
npx playwright install chromium
npm run record-demo
~~~

Recording uses the currently running React, FastAPI, PostgreSQL, Odoo 19, n8n, and Mailpit and does not connect to real payment, supplier email, or Feishu. The browser recording script creates a synthetic high-value purchase request and one local digest email; the response-loss scenario is generated by `run-erp-unknown-demo.ps1`. Before recording, check that the screen contains no `.local` files, passwords, or API keys. The generated source video is staged in Git-ignored `.local/recording/`; when the script completes, it outputs a shareable MP4 and SRT to `docs/assets/`.

## Timeline

The Chinese subtitles explain section by section the business problem, the two n8n flows, the human role of department and finance, independent Odoo read-back, and manual verification when the external result is uncertain.
